# 内置预训练模型标注 · 制作计划

> 目标：让用户不花钱就能标注 —— 软件内置 YOLO-World 等预训练模型，用户在对话里直接选一个就能标注，并把「本机 0 元」与「云端 API」的精度/成本摆在同一张表里对比。
>
> 本文件需镜像到两处：`C:\Users\zhy23\Desktop\内置预训练模型标注-制作计划.md` 与仓库 `plans/内置预训练模型标注-制作计划.md`。

## 一、确认过的三个决定

| 决策 | 选择 |
|---|---|
| 权重分发 | **混合**：小模型（yolo11n 系列 + YOLO-World S）随安装包内置；大模型与文本编码器在应用内按需下载（SHA-256 校验、断点续传） |
| Python 环境 | **加「一键准备本地推理环境」**：检测本机 Python → 建独立 venv → 国内镜像装依赖 |
| 省钱对比 | **首版就做**：内置模型跑出的结果能进同一张指标对比表，并显示本机成本 ¥0 |

## 二、现状（调研结论，决定了方案怎么落）

现有链路其实已经有一整条「本地模型」通路，缺的是三块：

**已有的（直接复用，不要重写）**
- 登记 → 哈希校验 → 作用域授权 → 加载 → `flow.local` 步骤标注：`engine/.../LocalModels.java`、`LocalRuntime.java`、`LocalInference.java`、`LocalRuns.java`
- Python 推理 worker（stdin/stdout 行级 JSON，协议 v1）：`inference/worker.py`
- 本地运行**已经**把候选版本写进 `versions` 表且 `source='local'`（`RunResults.java` 的 `String source=...equals("local")?"local":"api"`）
- 模型选择入口壳：`renderer/src/ModelPicker.tsx`（picker-popover 模式）、`renderer/src/LocalModels.tsx`

**缺的三块**
1. **没有内置模型目录**。所有模型必须用户自己找 `.pt` 文件、用文件选择器授权；`LocalModels.register` 只认绝对路径的本地文件。
2. **没有开放词汇能力**。全仓库搜不到 grounding / open-vocab / CLIP / set_classes；`predict` 的 payload 白名单里没有任何文本提示字段，类别只能是模型自带的固定数字表。
3. **界面上没有「选模型去标注」的入口**。本地标注只能靠对话里让 Agent 配 `flow.local` 步骤，或走流程编辑器。

**两个必须正视的硬约束**
- YOLO-World 要 CLIP 文本编码器才能编码类别名，ultralytics 默认会联网下载。当前项目全程 `YOLO_AUTOINSTALL=false`、离线优先 —— 必须显式接管，不能让它在用户不知情时联网。
- Python 运行时**不在安装包里**（`build/electron-builder.cjs` 只打包了两个 `.py`）。`scripts/desktop-runtime.mjs` 是 Java 21 的 jlink 运行时，跟 Python 无关。

**一个意外的好消息**
「本地结果进不了对比表」不是架构问题，只是 `Evaluations.java` 里这一行：
```java
Store.one(c,"SELECT data FROM versions WHERE asset_id=? AND version=? AND source='api'",...)
```
改成 `source IN ('api','local')` 即可打通。这是第 6 步成本很低的原因。

## 三、总体设计

新增五个零件，全部挂在现有架构上，不新建并行体系。

```
用户 → 对话输入卡 [内置模型 ▾]
          │
          ├─ 模型库(设置→软件 AI 配置→模型库)  ← desktop/model-library.ts
          │     内置(<安装目录>/resources/models) / 下载(<存储根>/models)
          │     校验 SHA-256 → 自动登记 local_model(origin=builtin) → 自动授权
          │
          └─ flow.local 步骤 → LocalRuns → Java LocalRuntime → worker.py
                                            │
                                            └─ 开放词汇模型：textClasses → 词表缓存
                                               (命中内置词表 = 零下载；未命中 = 一次性 CLIP)
                                                     ↓
                                              写 versions(source='local')
                                                     ↓
                                        Evaluations 对比表（云端 API vs 本机 ¥0）
```

**零件 1｜模型目录（`shared/model-library.ts`，新）**
`MODEL_CATALOG: CatalogModel[]` 单一声明源，字段：`id / name / taskType / openVocabulary / fileName / sizeBytes / sha256 / tier('bundled'|'download') / group / downloadUrl / mirrorUrls / license / note`。

首版清单（体积以打包实测为准，这里只给量级）：

| 分组 | 模型 | 任务 | 分发 |
|---|---|---|---|
| 开放词汇 | YOLO-World v2 S | detect（开放） | 内置 |
| 开放词汇 | YOLO-World v2 M | detect（开放） | 下载 |
| 开放词汇 | CLIP 文本编码器 ViT-B/32 | — | 下载（一次性） |
| 通用检测 | yolo11n / yolo11s | detect | 内置 / 下载 |
| 分割 | yolo11n-seg | segment | 内置 |
| 关键点 | yolo11n-pose | pose | 内置 |
| 旋转框 | yolo11n-obb | obb | 内置 |
| 分类 | yolo11n-cls | classify | 内置 |

内置合计目标 < 60 MB。

**零件 2｜模型库运行时（`desktop/model-library.ts`，新）**
- 目录：内置 `<安装目录>/resources/models/`；用户态 `<存储根>/models/<catalogId>/<version>/<fileName>`，文本编码器放 `<存储根>/models/text-encoder/`，Python venv 放 `<存储根>/python-env/`。
- `status()` / `install(catalogId)` / `remove(catalogId)`；下载走 `Range` 断点续传，落 `.part` 后 rename，完成后核对 SHA-256，失败不留半份文件。
- 模型目录解析复用 `desktop/storage-paths.ts` 里 `validateTrainingRoot` 那套「独立可配置目录」的既有模式（训练产物目录就是这么做的），**不动 `PATH_KINDS`**，避免影响存储迁移的既有验收。

**零件 3｜一键启用即授权**
- `LocalExecutionSettings` 新增 `trustModel(path, hash)`：把模型库路径按当前数据作用域写进 `localModelGrants`，等价于用户手选文件。
- 启动引擎时 `desktop/main.ts` 把这些路径随 `localModelAuthorizations` 下发 —— **哈希核对逻辑一字不动**，安全性不降级，只是省掉文件选择器。
- `LocalModels.register` 增加可选 `origin`(`user`/`builtin`/`downloaded`) 与 `catalogId`，`publicModel()` 透出；默认 `user`，向后兼容。

**零件 4｜开放词汇推理**
- `inference/worker.py`：
  - `load` payload 增加 `openVocabulary`；为真时用 `ultralytics.YOLOWorld` 构造，返回体加 `openVocabulary: true`。
  - `predict` payload 增加 `textClasses: string[]`（1–200 条，去重，单条 ≤ 100 字符）。处理顺序：
    1. 算 `vocabKey = sha256(JSON.stringify(textClasses))`；
    2. 查 `<vocabularyCacheDir>/vocab/<vocabKey>.npz` → 命中则 `model.set_vocab(pe, names)`，**完全不碰网络**；
    3. 未命中 → 查内置词表（`inference/vocab/`，构建期生成的 COCO80 + 常见中文类别名嵌入）；
    4. 仍未命中 → 用本地 CLIP 编码，`download_root` 指向 `<存储根>/models/text-encoder/`，`YOLO_AUTOINSTALL=false` 下**若本地没有编码器就抛 `vocabulary_encoder_missing`**，由 UI 提示一次性下载，绝不静默联网；
    5. 编码结果写回缓存。
  - 类别仍是 `{0: 'person', 1: 'car'}` 形式，`classMap` 语义不变 —— 只是键从「模型固有类别号」变成「textClasses 下标」。**协议与上层的映射机制零改动。**
  - 返回体加 `vocabularyHash` / `vocabularySource('cache'|'builtin'|'encoded')`，便于复现与审计。
- Java：`LocalRuntime.validateParameters` 的 `keys(...)` 放行 `textClasses`；`freeze` 在开放词汇模型下改为按 `textClasses` 长度派生期望键集合，并把 `textClasses` 冻结进快照；`LocalInference` 透传；`LocalRuns.create` 的 `FlowPlans.keys(...)` 放行 `textClasses`。
- `shared/vocabulary.ts`（新）：`deriveClassMap(textClasses, projectClasses)` —— 先按项目类别名精确匹配（trim + 大小写不敏感），再查中文别名表，**未命中的一律置 `null` 并在 UI 里显示成「忽略」，等用户确认**（引擎对「明确忽略」有硬要求，不能静默吞掉）。
- `desktop/engine.ts` 启动参数增加 `localVocabularyCacheDir`。

**零件 5｜对话内选模型（沿用既有交互范式）**
- `renderer/src/LocalModelPicker.tsx`（新）：紧凑触发按钮 + `picker-popover`，与 `FlowPicker`/`ModelPicker` 并列在输入卡工具行。
- 选中后**只把提示词写进输入框**（与 `FlowPicker` 完全一致的模式），不直接执行、不偷偷计费。
- 已启用模型 ≤ 5 个直接列出，其余折叠成「还有 N 个 · 全部」—— 符合「列表默认收敛」的既有偏好。

**零件 6｜一键准备本地推理环境**
- `desktop/runtime-setup.ts`（新）：探测 `py -3.11` / `py -3` / `python`（要求 3.10–3.12）→ `python -m venv <存储根>/python-env` → 用国内镜像 pip 安装**固定版本**的 `ultralytics` + CPU 版 `torch`/`torchvision` → 写 `autolabel-env.json` 记录版本 → 成功后自动写入 `preferences.localPythonPath` 并调 `local.runtime.configure`。
- 安装进度按 stdout 行解析后走既有 `autolabel:event` 事件通道推给界面。
- 失败/离线时明确报错，并保留原有「手动选择 Python」路径（折叠在「高级」里）。

**零件 7｜省钱对比**
- `Evaluations.java`：`source='api'` → `source IN ('api','local')`，结果里带 `candidateSource`。
- `Costs.runView` 对无 provider 的本地运行做容错（不能因为 `providerId` 为空就抛错）。
- `EvaluationReruns.prepare` 的 scheme 增加 `kind: 'api' | 'local'`：本地方案不需要凭据、不占请求预算（`planned`/`estimated` 不计入、`Costs.reserve` 跳过），建单复用 `LocalRuns.insert(...)`（同包可见）。
- `renderer/src/RerunPanel.tsx` 加「内置模型」方案类型；`QualityCenter.tsx` 指标表加「成本 / 耗时」列（本地显示 `¥0 · 本机 123 ms/张`）。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| YOLO-World 的 CLIP 编码器在离线环境下被 ultralytics 偷联网 | worker 显式接管 `download_root`；本地无编码器时抛 `vocabulary_encoder_missing`；验收用例里专门断言「不得联网」 |
| 内置权重让安装包膨胀 | 只有 yolo11n 系列 + YOLO-World S 内置（目标 < 60 MB）；大模型与 CLIP 走按需下载；`check:models` 在打包前卡住体积与哈希异常 |
| 开放词汇的类别名是中文，匹配不上项目类别 | `deriveClassMap` 中文别名表 + 未命中项在 UI 显式标为「忽略」可改；绝不静默丢弃 |
| 本地结果进对比表后指标口径被误读 | 指标算法 (`Matching.java`) 与真值集 (`EvaluationSets`) 一行不改，只放开来源过滤；对比表标注 `candidateSource` |
| `EvaluationReruns` 加本地方案牵动预算/事务 | 本地方案不占请求预算、不走 `Costs.reserve`；若第 6 步实施中发现侵入过大，**降级方案**：先只交付「已有运行对比」（第 6 步前半段已足够让本地行出现在表里），真跑对比拆到下一步 |
| 一键装依赖体积大、国内网络不稳 | 固定版本 + 国内镜像 + 进度可见 + 失败保留原配置；GPU 版 torch 作为「高级」选项，默认 CPU 版 |
| 内置模型与用户自有模型混淆 | `LocalModel` 增加 `origin` 字段，模型库与本地模型列表分区展示，内置的不可被用户覆盖 |

---

## 六、明确不做的事

- 不内置 Python 解释器与 torch（走一键 venv 方案，安装包不膨胀 2~3 GB）
- 不引入任何模型**自动**下载：所有下载都由用户在模型库里显式点击触发
- 不改动指标算法、真值集机制与 `Matching.java` 的任何口径
- 不改动现有「用户手选模型文件 + 哈希授权」的安全模型，只是给内置来源加一条等价通道
- 不做模型微调/蒸馏（训练功能已存在，本计划不碰 `train_worker.py`）
