# 人工标注参考示例 · 实施计划

> 目标：用户点「开始标注」（云端 AI 自动标注）时，若项目内还没有可用的人工参考示例，先用一次弹窗说明价值并给出选择；确认后随机抽 5–10 张未标注图片进入人工标注，保存确认后自动作为参考示例随该次运行一同发给模型。
>
> 本计划只描述改法与验收口径，不含实现代码。

## 二、五处设计决策（已定，不再需要确认）

| # | 议题 | 决策 | 定这条的理由 |
|---|---|---|---|
| 1 | 抽样放在哪一层 | **新增引擎命令 `asset.sample`**（`Projects.java` + `Engine.java` 路由 + `Maintenance.READ_ONLY`） | `asset.list` 单页上限 500，渲染进程要凑够随机样本得拉全项目，素材上万时卡顿明显。引擎侧 `ORDER BY RANDOM()` 是一条索引查询，且与 `Projects.listAssets` 既有分工一致 |
| 2 | 参考示例是否沉淀到资源库 | **不沉淀**。示例就是「本项目里 `confirmed` 的素材」，随项目生命周期存在 | `resource.reference` + `ReferenceDialog` 已能手工把人工版本固化成跨项目资源，那是另一条独立能力。自动沉淀会引出版本副本、失效引用、跨项目类别映射一整套问题，收益不匹配复杂度 |
| 3 | 抽样数量与接口图片上限冲突 | **动态取 `limit = min(10, provider.maxImages - 1)`**，弹窗显示真实张数；`maxImages ≤ 1` 时整个入口隐藏 | 引擎硬校验 `references + 1 ≤ provider.maxImages`（`Runs.java:57-58`）。写死 10 在常见的多图上限（8）下必然 422 |
| 4 | 「不再提示」作用域与失效策略 | **按项目**存 `project.settings.manualExample.promptDismissed`；示例**失效则重新提示** | 参考示例的有效性本身就是项目级事实，跟在 `annotationRegion` 同一处最自然。示例若被人工改动（退回 `candidate`）就不再是可信标准，继续静默会让用户误以为「配过了」，比多弹一次更糟 |
| 5 | 内置模型目标是否走此流程 | **不弹窗、不抽样，直接执行** | `local.run.create` 在引擎侧完全没有 reference 通道（`LocalRuns.java` 无相关代码），示例送不过去。弹窗会让用户以为参考已生效 |

决策 1、3 直接决定接口与 UI 结构；决策 2、4、5 收窄了范围，使本功能不触碰资源库与本机推理两条链路。

## 三、设计

### 3.1 数据结构

参考示例不新增表，直接用素材状态：

```
// project.settings 新增键
{
  "manualExample": {
    "assetIds": ["a1", "a2"],       // 已确认的参考示例素材 id，有序
    "confirmedAt": 1732000000000,
    "promptDismissed": false,         // 用户勾了「不再提示」
    "usedAt": 1732000100000           // 最近一次随运行发送的时间
  }
}
```

**有效性判定（每次打开弹层前算一次）**：`assetIds` 非空 ∧ 每个 id 仍属本项目 ∧ 状态仍是 `confirmed`/`modified` ∧ 数量 ≥ 1。任一不满足即视为「无有效参考示例」。

抽样结果（未落库，仅内存）：

```ts
interface ExampleSample { assetIds: string[]; taken: number }
// taken = 实际张数；不足 5 张时 taken < 5
```

### 3.2 接口设计

| 命令 | 位置 | 参数 | 返回 |
|---|---|---|---|
| `asset.sample`（新增） | `Projects.java` + `Engine.java:34` 路由 | `{projectId, limit(1..10), status?: 默认 'unlabeled'}` | `{ids:[...], total}`（`ORDER BY RANDOM()`） |

无新增写命令：示例状态复用 `annotation.save(confirm:true)`，提示状态复用 `project.update(settings)`。

**Agent 白名单**：`asset.sample` 是只读命令，需加入 `Maintenance.READ_ONLY` 集合，且**不**加入 `agent/tools.ts` 的工具定义——本功能是界面行为，不开放给对话模型自主抽样。

### 3.3 UI 交互

**触发点**：`DirectRun.tsx` 的 `start()` 开头，云端目标且判定为「无有效参考示例」且未勾过「不再提示」时，先弹 `ManualExamplePrompt`。

弹窗内容（新建 `renderer/src/ManualExamplePrompt.tsx`，用 `ui.tsx` 的 `Modal` + `Field`，不走 `confirmDialog`——后者只有两按钮，装不下复选框）：

- 标题：「先标注几张示例，AI 会照着你的标准标」
- 正文：「AI 会照你标的样例学你的标准。手工标 5–10 张，风格、框法、排除项都会一起发给模型，比只写提示词准得多。」
- 数量说明：`本次将抽取 N 张未标注图片`（N 按决策 3 动态计算）
- 主按钮：「立即标注示例」
- 次按钮：「跳过，直接用 AI 标注」
- 底部复选框：「不再提示」（勾选后随「跳过」一起落 `promptDismissed: true`；勾选后选「立即标注示例」也落盘）
- 副信息：`图片不足时按实际张数处理` —— 仅在项目未标注素材 < 5 时显示

**抽样与标注流程**（`ManualExampleFlow.tsx`）：

1. 点「立即标注示例」→ 调 `asset.sample`，`limit = min(10, maxImages-1)`；结果 `< 5` 张时按实际张数继续，`= 0` 张时提示「这个项目还没有未标注的图片」并直接回到标注弹层。
2. 结果写入 `sessionStorage`（键 `manual-example-queue`，含 `projectId` 与 `assetIds`）——**跨弹窗刷新保持进度，且不污染项目数据**。重复点击「立即标注示例」时先查该键，命中则续做而非重抽。
3. 打开一个 `Modal wide`，标题「人工标注示例 · 1/N」，内含 `AssetAnnotator`，复用 `ProjectOverview.tsx:321` 的传参方式（`classes` / `taskType` / `templateSettings` / `initialAnnotations`）。
4. 底部动作改为：「保存并确认并下一张」（主）/「保存并确认并结束」/「跳过这张」/「退出」。
   - 用 `AssetAnnotator` 已有的 `onSaved(asset)` 回调推进队列；`asset.status === 'confirmed'` 即入列。
   - 「跳过这张」不写入，从队列移除并前进。
   - 「退出」中途中断时，若已有 ≥ 1 张确认成功，**照常视为已有示例**并继续建任务。
5. 队列走完：把 `assetIds` 写入 `project.settings.manualExample`，清 `sessionStorage`，回到标注弹层并把 `referenceId` 置为这些 id（`DirectRun` 现有 `referenceId` 需从单选扩为多选 `referenceIds`，`resolveTargets` 的剔除逻辑对数组去重即可）。

**文案要点**：全程用「照你的标准标」而不是「训练」——这里不是训练模型，避免误导；不使用「few-shot / 样例对齐」等术语。

### 3.4 异常处理

| 场景 | 处理 |
|---|---|
| 未标注图片 < 5 张 | 弹窗内显示实际张数并说明；`= 0` 时禁用「立即标注示例」，只留「跳过」 |
| `maxImages = 1`（接口不支持多图） | 隐藏参考示例入口，`referenceAssetIds` 本就不可用 |
| 抽样中途用户刷新/退出 | `sessionStorage` 保留队列，重开标注弹层时提示「上次标注到 2/8，继续？」 |
| 中途取消 | 已确认的示例照常落 `project.settings`，不足则不落；不阻断标注流程 |
| `annotation.save` 版本冲突 | 复用 `AssetAnnotator` 既有的 `annotation_version_conflict` 处理（载入最新并提示），不新增逻辑 |
| `asset.sample` 失败 | 提示「抽取示例图片失败：{message}」，降级为直接执行 AI 标注，不弹二次错 |
| `run.create` 因参考被拒（`reference_invalid` / `reference_target_overlap` / `image_limit_exceeded`） | 捕获这三个错误码后自动重试一次（去掉 `referenceAssetIds`），并 toast：「示例未能随请求发送，本次已按无参考执行」 |
| 项目素材在抽样后被删除 | `run.create` 的 `run_assets_invalid` 由引擎既有校验兜底；队列中消失的项在 `annotation.save` 前用 `asset.get` 探测，缺失则跳过 |
| 本机模型目标 | 不弹窗、不抽样 |

## 五、验收标准（功能口径）

1. 项目无有效参考示例且未跳过 → 点「开始标注」（云端）必弹窗，且弹窗在真正创建运行**之前**。
2. 弹窗仅两个主选项 + 一个「不再提示」；三态（标注 / 跳过 / 勾选后跳过）均不产生半成品运行。
3. 抽样张数恒为 `min(10, provider.maxImages - 1)`，且不超过未标注素材总数；不足 5 张按实际张数并明示。
4. 标完的示例素材状态为 `confirmed`，出现在随后的 `run.create` 的 `referenceAssetIds` 中，且不出现在 `assetIds`（目标）里。
5. 「跳过」或已有有效示例或已勾「不再提示」→ 不弹窗，标注任务正常创建。
6. 参考被引擎拒绝时自动降级为无参考运行，用户收到明确提示，不出现失败弹窗。

**实现中修正的三处与原计划不同：**

1. **流程按钮不自己调 `annotation.save`。** 原计划让流程直接提交标注，但画布上的改动只存在于 `AssetAnnotator` 内部状态，从外面读到的 `asset.annotations` 是打开时的旧内容——那样会把用户刚画的框静默丢掉。改为由流程按钮驱动 `AssetAnnotator` 自己的「保存并确认」，再用 `onSaved` 推进队列。
2. **参考帧由单选改为多选。** few-shot 场景下单张参考的效果明显弱于多张，且既然示例流程一次就标 5–10 张，下拉单选装不下。
3. **弹窗条件里加了「池子为空直接放行」。** 没有未标注图片时弹一个只有「跳过」可点的空窗没有意义。
