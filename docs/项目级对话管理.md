# 项目级对话管理

## 1. 目录结构

存储根下新增 `projects/`，取代原先扁平的 `chats/`。每个项目一个文件夹，对话、素材、上下文都在里面：

```
<存储根>/                                  # 默认 <安装目录>/AutoLabelData
├─ datasets/                               # 划分好的训练集（不变）
├─ uploads/                                # 受管原图（不变）
├─ projects/                               # 新增：项目文件夹根
│  ├─ .layout-migrated                     # 迁移完成标记（见 §4）
│  ├─ <projectId>/
│  │  ├─ chats/                            # 该项目的全部对话
│  │  │  ├─ index.json                     #   会话索引（置顶/归属/素材范围）
│  │  │  ├─ <sessionId>.jsonl              #   逐条追加的消息
│  │  │  ├─ <sessionId>.memory.json        #   派生对话时冻结的历史摘要
│  │  │  └─ .trash/                        #   该项目的回收站（7 天）
│  │  ├─ media/                            # 该项目的素材基准图（引擎写入）
│  │  ├─ files/                            # 项目级附件
│  │  └─ context.json                      # 项目共享上下文：新对话的默认素材范围
│  └─ _unassigned/                         # 无归属的历史会话收容目录
└─ chats/                                  # 旧版扁平目录，仅作为迁移来源
```

**为什么数据库没拆。** 标注、素材索引、运行记录仍在引擎的单个 SQLite 库里（`assets` 等表都带 `project_id`，查询口径不变）。按项目拆库要动全部查询、外键与备份链路，风险远大于收益；而对话、素材、上下文天然一项目一份，在文件层隔离没有一致性代价。因此「项目之间互不干扰」由目录结构保证，业务数据仍由 `project_id` 保证。

## 3. 功能落点

1. **项目内新建对话**：`chat.history.fork`。新对话自动归属该项目，继承项目共享上下文（最近一次使用的素材范围）与历史摘要；项目文件、类别、配置本就按 `projectId` 取，无需重新导入。
2. **切换 / 查看 / 重命名 / 删除**：侧栏按项目分组展示；重命名、置顶、删除作用于单条会话；删除前弹确认，并沿用既有回收站（7 天可恢复）。
3. **按项目隔离**：见 §1。会话、素材、上下文各自落在项目目录内，删除只影响本项目。
4. **迁移**：见 §4。

## 4. 数据迁移

升级后首次进入「设置 · 对话记录」，点「迁移到项目文件夹」：

- 按 `projectId` 把旧 `chats/index.json` 中的每条会话搬进对应项目目录；没有归属的进 `_unassigned`，不会消失。
- 逐条重建项目索引，迁移完侧栏立刻可见。
- **只复制、不删源目录**，并在界面上如实说明源路径保留，确认无误后可自行删除。
- 完成标记 `.layout-migrated` 只在零失败时写入；有失败则保持未迁移状态，可重试。

素材侧无需迁移：新导入写入 `projects/<id>/media/`，历史素材继续按库中记录的绝对路径读取，两种布局并存可用。

> 实现中修正过一处判断失误：最初用「`projects/` 目录是否存在」作为迁移标记，但正常使用时 `ensure()` 就会建出该目录，会让升级用户的历史对话永远被判为「已迁移」而留在原地。改为显式的标记文件，并有回归测试钉住。

## 5. 验证方式

```bash
npm run test:desktop     # 165 项：153 通过 / 0 失败（基线 141，新增 8 项隔离与迁移用例）
npm run check:desktop    # 桌面端类型检查
npm run check:renderer   # 渲染层类型检查
npm run check:contract   # 跨层契约：命令 216 / 引擎 182
npm run build:desktop    # 主进程产物
npm run build:renderer   # 渲染层产物
scripts/engine-build.ps1 -Test   # 引擎：689 项断言
```

覆盖的关键链路：

- **隔离**：两项目的消息文件互不串内容；按项目过滤与跨项目全量列表都正确；按 id 读取不依赖调用方知道归属。
- **搬迁**：会话改归属时文件搬迁而非复制，收容目录不残留。
- **回收站作用域**：删除 A 项目对话不影响 B；回收站条目带归属，恢复写回原项目。
- **迁移**：迁入正确目录、无归属进收容目录、源目录保留、重复执行跳过。
- **迁移端到端**：旧目录 → 搬文件 → 重建索引后，历史对话在侧栏可见、标题与消息完整（只搬文件不补索引等于迁空壳，这条专门钉住）。
- **删除项目保留回收站**：素材与上下文清空，`chats/.trash` 仍在——否则「7 天可恢复」会落空。

手工回归建议：建两个项目各发一轮对话 → 检查 `projects/<id>/` 下文件分开 → 删除其中一个项目的对话，确认另一个不受影响 → 设置里迁移一次，确认历史可见且旧目录仍在。

## 6. 已知边界

- 引擎的业务数据仍是单库，隔离靠 `project_id` 与目录结构，未做物理分库。
- 项目删除后项目文件夹会保留（仅当其中还有回收站内容时），用于兑现恢复承诺；可在恢复期结束后手工删除。
- **UI 验收（`check:*-ui`）在当前环境无法执行**：Electron 无法开窗，所有 UI 冒烟项一致超时或崩溃（含改动前的基线同样如此），属环境限制而非本次改动。相关界面改动（侧栏删除确认、迁移入口、设置项改名）只经过类型检查与生产构建验证，建议在有图形界面的机器上补跑 `npm run check:sidebar-ui` 与 `npm run check:storage-ui`。
