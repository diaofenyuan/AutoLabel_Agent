# 标注任务自动生成数据集版本设计

## 目标

一次标注任务进入终态后，系统自动为当前项目创建一个不可变数据集版本。用户不再需要先手工打开“数据集版本”再创建快照，训练可以直接读取该任务产生的最近就绪版本。

## 终态口径

- `completed`：自动生成版本，范围为当前项目中有正式标注的素材。
- `completed_with_errors`：自动生成版本，保留已成功写入的标注；失败样本不进入版本范围，并在版本来源信息中保留原任务状态。
- `needs_attention`、`cancelled`、`failed`、运行中状态：不自动生成版本。
- 单张人工编辑、导入标签、轨迹候选保存不单独生成版本，避免一次操作产生大量版本；它们会在下一次标注任务完成后被当前项目快照纳入。

## 数据流

1. `Runs.settle` 在事务内将运行置为终态并写入 `run.completed` 或 `run.completed_with_errors`。
2. 事务提交后调用一次自动版本协调器，避免在运行状态事务中嵌套数据集版本事务。
3. 协调器按 `runId` 做幂等检查；同一任务无论收到多少次终态回调，只允许一个自动版本记录。
4. 自动版本使用现有数据集版本构建器，默认配方为 `annotationScope=labeled`、默认来源组划分和默认种子；版本数据增加 `sourceKind=annotation_run`、`sourceRunId` 与来源任务摘要。
5. 版本构建成功后继续发出既有 `dataset.version.ready` 事件；创建阶段发出 `dataset.version.created`，事件负载携带 `sourceKind` 和 `runId`，界面据此刷新项目概览。

## 失败与恢复

- 没有有效标注、体检阻断、复制失败等情况仍保留自动版本记录，状态为 `failed`，并写入可读 failure；不伪造可训练状态。
- 已有失败版本沿用现有“重试生成”能力；重试仍保持同一版本号和来源任务关联。
- 自动版本创建异常不能回滚或改写已完成的标注任务；错误通过事件和版本详情呈现。

## 训练闭环

- 助手读取数据集版本列表时优先看到最新自动版本，并明确 `building` 版本需等待、`failed` 版本需处理原因、`ready` 版本可建立训练快照。
- 训练快照仍只接受 `versionId`，并只允许从 `ready` 版本创建，防止训练读取半成品。
- 项目概览说明“标注任务完成后自动生成版本”，数据集版本列表保留手工新建入口作为高级复现能力。

## 验证

- 引擎单测：终态触发、部分失败范围、阻断失败记录、重复回调幂等、取消/未知状态不触发。
- 跨层契约：自动来源字段不暴露绝对路径，训练仍拒绝非就绪版本。
- UI 验收：完成真实标注任务后，项目概览出现自动版本并能打开详情；版本就绪后可继续创建训练快照。
