# 项目派生对话与历史摘要设计

## 目标

从项目入口新建对话时，保留项目工作上下文：把项目全部历史会话压缩为可控长度的摘要，并继承最近一次会话实际使用的素材范围和人工参考。新会话拥有自己的消息记录，不把旧会话消息混入当前对话列表。

## 范围

- 项目概览提供“新建对话”，项目侧栏操作菜单提供同一入口。
- 当前项目已有会话时，侧栏“新对话”与项目入口统一走派生流程；没有项目时保留欢迎页流程。
- 摘要由桌面本地根据已落盘的会话消息确定性生成，不调用额外模型，不读取项目外会话。
- 发送新消息时，助手收到摘要作为受限的背景上下文；摘要内容视为历史数据，不能改变工具安全边界。
- 最近会话的素材范围和人工参考跟随新会话；发送前仍按当前项目素材权限校验。

## 数据设计

### 会话摘要

在共享会话类型中增加项目工作上下文：

- `ChatMaterialContext`: 处理范围（`current`、`project`、`page`、`selected`）、素材 ID、人工参考素材 ID 和共享参考资源。
- `ChatMemoryConversation`: 历史会话 ID、标题、更新时间、消息数、首条用户目标、最近助手结论和该会话最近素材上下文。
- `ChatMemorySnapshot`: 生成时间、项目 ID、历史会话摘要列表及因长度上限省略的数量。
- `ChatSession` 增加可选的 `memory` 与 `context`；`ChatSessionSummary` 保存最近一次发送的 `context`，用于重载和派生。

快照写入独立的 `<sessionId>.memory.json`，避免把完整历史复制进索引；删除、恢复、导出和状态统计一起处理该文件。旧版本没有快照或上下文时按空值兼容。

### 派生接口

增加 `chat.history.fork`：

- 输入新会话 ID、项目 ID、项目名，以及可选的提供商、模型和显式源会话 ID。
- 桌面侧读取该项目全部会话并生成摘要，选择最近一条有消息会话的上下文；没有历史时创建空快照。
- 返回新会话摘要与快照，操作在 ChatStore 串行队列内完成。

### Agent 上下文

在 Agent 上下文增加受限的 `memorySummary` 文本。渲染层把快照格式化为中文摘要并随请求发送；Agent 校验长度后把它放进模型系统背景中，工具环境仍只使用显式素材 ID和项目 ID。摘要限制为 60000 字符；单条会话摘要截断，超出数量通过 `truncatedCount` 说明。

## 数据流

1. 用户从项目概览、项目菜单或侧栏点击“新建对话”。
2. 渲染层调用 `chat.history.fork`，桌面侧建立新索引并保存摘要快照。
3. 渲染层把返回的上下文载入新会话状态，并将继承的素材选择映射到当前项目。
4. 用户发送消息时，Agent 请求携带摘要、当前消息和本次处理范围；桌面记录只追加当前会话消息，并更新最近素材上下文。
5. 下次从该项目派生时，新的快照重新从项目全部历史会话生成，确保历史会话的新增内容会进入摘要。

## 失败与兼容

- 历史会话损坏、摘要文件损坏时跳过损坏条目并保留警告，不阻断新会话创建。
- 源会话被删除后，已创建的新会话仍保留独立快照。
- 继承的素材 ID不再属于项目时，发送请求沿用既有 Agent/引擎校验并给出可读错误。
- 旧索引和旧 JSONL 不含新增字段时正常读取。
- 生成摘要不修改任何旧会话消息。

## 验证

- ChatStore 单测覆盖：全项目摘要、最近素材上下文、快照持久化、删除/恢复和损坏快照兼容。
- Agent 单测覆盖：摘要进入模型请求、超长摘要拒绝或截断、工具上下文不因摘要扩大素材权限。
- 渲染层类型检查和已有桌面项目入口验收覆盖：项目概览与侧栏新建对话均留在项目内，并显示继承提示。
