- **实测踩坑（最重要的三条，已冻结进 COORDINATION.md）**：
  1. Windows 上只要有线程阻塞在 `sys.stdin.readline()`，之后再 `import torch/ultralytics` 就永久挂起
     （实测：`os.read(0)` 阻塞同样触发；换成主线程内联训练 + 控制线程只处理 cancel 就正常）。
     最终结构：启动时 `preload()` 依赖 → 控制线程只做 cancel/shutdown 回执 → 训练在主线程内联执行。
     曾先怀疑是「在后台线程导入」，改成主线程导入仍挂起才发现真因是 stdin 阻塞。
  2. `emit()` 必须写模块级 `protocol = sys.stdout` 引用：训练期用 `redirect_stdout(sys.stderr)` 收日志时，
     若 emit 直接取 `sys.stdout` 会把协议行写进 stderr。
  3. ultralytics 8.4 训练循环读 `trainer.stop`（不是 `stop_training`），且 `on_fit_epoch_end` 在训练收尾会
     以同一轮次再触发一次；不处理会多出一轮、取消也不生效。取消后还要区分「真的提前停了」与「跑完了」，
     后者按 succeeded 报告，不虚报为 cancelled。
